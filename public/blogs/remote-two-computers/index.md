## 起因

我实习时用的是公司的 Windows 电脑，自己的 Mac 不方便在工位上拿出来。但我很多自己的东西（学习笔记、个人项目、平时探索的新领域）都在 Mac 上，用的也是我自己付费的 Claude 账号。

我想要的效果很简单：**坐在工位上，不拿出 Mac，也能像同时有两台电脑一样，操作 Mac 上的东西。**

整个过程我是和 Claude 一边聊一边折腾的，记录一下踩过的坑和最后的方案。

## 第一次尝试：SSH

最直觉的办法是 SSH 登录到 Mac。

1. Mac 上打开「系统设置 → 通用 → 共享 → 远程登录」
2. Windows 上生成一对密钥：

   ```bash
   ssh-keygen -t ed25519 -C "my-work-pc"
   ```

3. 把公钥（`id_ed25519.pub` 里那一行）加到 Mac 的 `~/.ssh/authorized_keys`
4. 连接：`ssh 用户名@Mac的IP`

结果报错：

```
kex_exchange_identification: Connection closed by remote host
```

### 第一层原因：代理软件的 TUN 模式

查路由发现，发往 Mac 的流量走的是代理软件（Clash Verge）的虚拟网卡，而不是真实网卡。TUN 模式会**接管所有流量**，连局域网地址都会被它拦下来，SSH 握手直接被掐断。

这里有个容易搞混的点：

- **系统代理的"绕过列表"**：只管走系统代理的程序，TUN 模式不看它
- **TUN 模式**：只认代理软件自己的规则

所以要在规则里加一条让目标网段直连：

```
IP-CIDR,<Mac所在网段>/16,DIRECT,no-resolve
```

加完再试，**还是不行**。

### 第二层原因：两台电脑根本不在一个网络

为了排除代理的干扰，我直接绑定真实网卡去连：

```bash
ssh -b <公司电脑真实IP> 用户名@Mac的IP
ping -S <公司电脑真实IP> Mac的IP
```

结果：SSH **连接超时**，ping **100% 丢包**。

这说明问题根本不在代理，而是**路本身不通**。公司电脑在有线网的一个网段，Mac 在另一个网段，可能是 Wi-Fi 和有线网被隔离，也可能 Mac 根本不在公司网络里。而我想要的场景，恰恰就是 Mac 不在身边，所以 SSH 这条路天然走不通。

想打通的话，就得用 Tailscale 这类组网工具。但这等于在公司网络里开了一条通往个人设备的通道，我觉得不合适，就放弃了。

**收获：排查网络问题要一层一层剥。** 先看流量走哪张网卡（代理），再绕开代理直连真实网卡看通不通（路由/隔离），每一步都能排除一个嫌疑。

## 最终方案：Claude Remote Control

后来发现，我真正想要的其实不是"登录 Mac 的终端"，而是**在公司电脑上继续 Mac 上的 Claude 会话**。这个 Claude 的 Remote Control 就能做到。

它的原理是：会话**在 Mac 上运行**，数据经过 Claude 的服务器加密转发，所以**不需要两台电脑在同一个网络**，SSH 碰到的那些网络问题都不存在。

实际用下来，有几个要注意的地方：

- **按会话开**：每个会话要单独打开远程，而且要**先聊过一句**才能在另一台电脑上看到。想批量把老会话都打开，是不行的
- **不能在远端新建会话**：要先在 Mac 上开好。我的做法是出门前开几个备用会话：远程交流 1、2、3……
- **Mac 要醒着**：插电、不休眠（「系统设置 → 电池 → 显示器关闭时防止自动进入睡眠」，或者在终端跑 `caffeinate -d`）、联网、Claude 应用开着。Mac 一睡着，在公司是叫不醒的

现在的体验就是：公司电脑的 Claude 侧边栏里，能看到 Mac 上的会话，点进去就能让它在 Mac 上读写文件、跑命令、提 PR。这篇博客本身，就是这样从公司电脑"遥控"Mac 提交上来的。

## 关于"公私分开"的一点思考

折腾过程中我想得最多的，其实是边界问题：

1. **私人的东西留在 Mac 上**：在 Mac 的会话里产生的文件就存在 Mac 上，公司电脑只是一个"显示器"。这样也不存在以后要"迁移"的问题，因为它从来就不在公司电脑上
2. **公司的东西不往个人设备搬**：代码、配置、客户资料、内部文档，一律不碰。这是红线
3. **公司电脑上看到的就当作是公开的**：屏幕上显示的东西、打的字，都在公司电脑上。不想被看到的，就不要从公司电脑去操作
4. **账号要分清**：用自己付费的账号做自己的事，没有心理负担
5. **离开的时候清干净**：实习结束时，公司电脑上退出账号、清掉本地数据

技术上能做到的事很多，**但"能做"和"该做"之间，要自己划一条线**。

## 一点真实的感想

下午有空，就顺手把这套"远程互通"搭了起来，相当于把公司电脑上的 Claude 和我自己的 Claude 接到了一起。搭完之后我认真想了一下，它对我到底有什么用。

**第一，工位上的时间可以用来探索自己的东西。** 接下来很长一段时间，我大部分时间都在公司电脑前。有了这条通道，我可以在 Windows 上，用自己 Mac 上的 Claude 和自己的 token，去探索很多领域：学习、个人项目，甚至投资这类和工作无关的方向。

**第二，我也动过"从公司带点东西走"的念头。** 比如代码、做过的东西，想留一份在自己手里。但真想清楚之后，发现想法和实际做差别很大：公司的代码和资料受保密约定约束，搬到个人设备上就越线了，这条路不能走。真正能带走的，是我在这里学到的思路、踩过的坑和总结出来的经验，用自己的话写成笔记和博客，比如上一篇后端八课那样。

所以这些更多只是感想，真正落地的时候，还是要回到上面那几条边界。

## 总结

| 方案 | 结果 | 原因 |
| --- | --- | --- |
| SSH 直连 | ❌ | 代理 TUN 拦截 + 两台电脑不在同一网络 |
| 组网工具（Tailscale 等） | 没试 | 会在公司网络里开通往个人设备的通道 |
| Claude Remote Control | ✅ | 经服务器转发，不受网络隔离影响 |

最后的心得：**先想清楚自己真正要的是什么，再选工具。** 我一开始以为要的是 SSH，其实要的只是"继续 Mac 上的会话"，换个角度，问题就简单多了。
